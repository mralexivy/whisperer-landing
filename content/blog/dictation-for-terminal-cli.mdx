Dictation in the terminal used to mean trying to say `docker compose -f docker-compose.prod.yml up --build -d` out loud. That's still a bad idea. What changed is that a lot of terminal work now happens through CLI agents like Claude Code and Codex, and those want plain English. That's where voice is genuinely faster.

Whisperer works in Terminal, iTerm2, Warp and any other terminal: hold Fn, speak, release, press ⌘V.

## Why not dictate shell commands directly?

Shell syntax is mostly symbols: dashes, dots, slashes, quotes, pipes. Whisperer doesn't have spoken symbol commands, so "dash dash build" comes out as words. Even with a tool that does, a long command dictated symbol by symbol is slower than typing it and much slower than asking an agent for it. Tab completion and shell history are already good at the rest.

## Claude Code and Codex by voice

Click into the agent's input, hold **Fn**, describe the task, release. Whisperer copies the text and shows a **Copied ⌘V** toast. Press **⌘V** and check the prompt before you press Return.

## Commit messages

Many teams don't end a commit subject with a full stop. Whisper usually adds one, so delete it before you commit if your team cares.

## Get tool names right

Speech models trained on everyday speech mishear CLI vocabulary. Add the terms you say to the [personal dictionary](/features/personal-dictionary) once:

| What it hears | Correct form |
|---|---|
| cube control | kubectl |
| post gress | PostgreSQL |
| engine x | nginx |
| home brew | Homebrew |
| your service and cluster names | your spelling |

For a handful of names you say constantly, the **Prompt Words** tab on the Dictionary page tells the speech model to expect them. See [setting up the dictionary](/blog/personal-dictionary-setup).

## Things to know in a terminal

<Callout type="info">
- **It's a paste.** Whisperer doesn't type into the terminal or press Return. You paste with ⌘V and decide when to run anything.
- **Watch the final full stop.** If you do paste text at a shell prompt, check the end of the line: a trailing period after a command or path will break it.
- **Multi-line text.** Agent prompts handle pasted paragraphs fine. At a bare shell prompt, read pasted multi-line text before pressing Return.
- **Long prompts.** Switch the shortcut to toggle mode (press once to start, once to stop) so you're not holding Fn for a minute.
- **Any shell.** zsh, bash, fish: the shell never sees Whisperer, only pasted text.
</Callout>

Whisperer recognises Terminal, iTerm2 and Warp as code apps, but it doesn't change the text there. The one per-app behaviour, dropping the full stop on one-line chat messages, applies only to chat apps. See [per-app dictation](/blog/dictation-for-per-app-profiles).

## Let your agent read what you dictated

With Pro, Whisperer can run a local [MCP server](/mcp). Claude Code, Codex, Cursor and other MCP clients can then search your dictation history and meeting transcripts. A practical use: dictate a long description of a bug once, then ask Claude Code to "find my dictation about the checkout bug and turn it into a failing test". The server is off by default and listens only on your Mac.

## When voice helps most in the terminal

- Long sessions with Claude Code or Codex, where most of what you type is instructions
- Explaining a problem while you read logs
- Commit messages and PR descriptions
- Days when your hands need a break

For short commands, flags and paths, keep typing. The split is the point.
